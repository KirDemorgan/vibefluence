# 0004. Запись только через ветку и MR, CI отключает репозиторий

## Контекст

Опубликованный документ должен попасть в default-ветку. Прямой пуш в защищённую ветку не гарантирован и обходит ревью-политику. Сервис не должен запускать чужие пайплайны и деплои.

## Решение

Публикация идёт так: ветка `vibefluence/<slug>-<id>`, коммит через Commits API, MR, мердж. Управление пайплайнами остаётся за подключаемым репозиторием: его `.gitlab-ci.yml` должен исключать пайплайны для веток с префиксом `vibefluence/` и для пользователя-бота, иначе пайплайн запустится на default-ветке после мерджа.

После создания MR сервис проверяет, не появился ли пайплайн. Если пайплайн есть или мердж запрещён настройками проекта, MR остаётся открытым и UI показывает причину.

## Последствия

- Нет собственных обходов CI (`[skip ci]`), поведение определяется конфигурацией репозитория.
- Администратору нужен шаблон `workflow:rules` и права бота на мердж.
- «Pipelines must succeed» несовместимо с автомерджем без пайплайна.
- Гонку «пайплайн ещё не создан» полностью устранить нельзя, проверка лишь страховка.
- Поведение GitLab проверяется на корпоративном инстансе вручную, до этого тестами на фейковом GitLab.
