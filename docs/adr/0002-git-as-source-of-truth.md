# 0002. Git как источник истины, без хранилища контента

## Контекст

Документы лежат в репозиториях GitLab, их десятки или сотни. Репозитории большие. Дублировать контент в собственную БД значит получить расхождения и необходимость синхронизации.

## Решение

Читаем только default-ветку проекта через GitLab API. Список файлов берём запросом дерева, ограниченным настроенными путями. Содержимое кэшируем по blob-id: он неизменяем, поэтому кэш не протухает. Поисковый индекс строится в памяти.

Собственное постоянное состояние ограничено рабочими копиями черновиков (см. ADR 0003).

## Последствия

- Файл из чужого MR не виден до мерджа, без отдельной логики.
- Отдельная БД не нужна, развёртывание проще.
- Скорость и доступность зависят от GitLab, поэтому нужны кэш, повторы и понятные ошибки.
- Обновление: webhook на push, периодический опрос как запасной путь, форс после собственного мерджа.
