# 0003. Draft как поле front matter

## Контекст

Нужен статус документа, при котором он не попадает в репозиторий автоматически. Статус ставит пользователь в UI или автор прямо в файле. Файл со статусом draft, пришедший в default-ветку через чужой MR, на сайте показываться не должен.

## Решение

Единый источник истины это поле `status` (`draft` или `published`) во front matter. Переключатель в UI правит то же поле в редакторе.

- В default-ветке файл со `status: draft` скрыт из дерева, поиска, списков и MCP; прямая ссылка возвращает 404.
- Файл без `status` считается опубликованным.
- Сохранение из UI со статусом draft создаёт рабочую копию на сервере и ничего не отправляет в GitLab.
- Публикация запускает поток ветки и MR (ADR 0004).

## Последствия

- Одно правило видимости для всех источников файлов.
- Рабочие копии нужно хранить на диске сервера и показывать в отдельном разделе.
- Возврат опубликованного документа в draft это отдельное действие через MR, в первой версии не входит.
