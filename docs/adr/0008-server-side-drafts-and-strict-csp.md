# 0008. Черновики на сервере и строгая CSP

## Контекст

Редактор должен сохранять работу, но запись в репозиторий допустима только через MR (ADR 0004). Хранить черновики в `localStorage` нельзя: их не увидит MCP и они пропадут вместе с браузером. Angular по умолчанию встраивает в `index.html` скрипт для критического CSS, из-за чего строгая CSP невозможна.

## Решение

Черновики UI и MCP хранятся JSON-файлами в `server.dataDir/drafts/<repo>/<id>.json`, запись атомарная, права 0600. Идентификатор считается от репозитория и пути. Черновик помнит blob основы, поэтому конфликт обнаруживается при публикации. В репозиторий файл попадает только после публикации.

В production-сборке фронтенда отключено встраивание критического CSS (`inlineCritical: false`), поэтому `index.html` не содержит inline-скриптов и сервер отдаёт `script-src 'self'`. Для стилей остаётся `'unsafe-inline'`: компоненты Angular и Taiga создают `<style>` во время выполнения, а nonce при статической раздаче невозможен.

## Последствия

- Черновики живут на одном экземпляре сервиса. Для нескольких реплик нужен общий том или отдельное хранилище.
- Потеря `dataDir` стоит только несохранённых черновиков, опубликованное хранится в GitLab.
- Стили с `'unsafe-inline'` слабее скриптов: XSS через стили ограничен, но не исключён. Основная защита остаётся в санитайзере Markdown.
- Дополнительная загрузка CSS блокирует первую отрисовку чуть дольше, чем при инлайне.
